# pricebook-update — 거래처 단가표 갱신 (수집 방식 ③)

> 실행 = 저장된 도구 3개를 순서대로. 결과는 **정본 데이터 갱신**(`.claude/references/sourcing-prices/{거래처}/` 정규화 CSV)이고,
> 소싱 조사 중이면 스키마① 원가 CSV의 ③행도 교체한다. 사람 개입 = intake 의 ❓ask 판정 건 확인 — 새 거래처는 **첫 확인 한 번**, 그 뒤는 자동.
> ⭐ **먼저 읽는 문서 = 거래처 문서** `sourcing-channels.md` §소싱처 레지스트리: 거래처 이름(정식 상호)·단가표를 보내는
> 메일 주소의 기준이다. 도구가 이 표에서 방식 «③» 줄을 읽는다 — 사용자에게 거래처 이름·주소를 묻지 않는다. 문서에 없는 거래처의 단가표는
> 옮기지 않는다 → 먼저 문서에 한 줄을 적는다. 거래처 폴더는 도구가 문서의 이름 그대로 만든다.
> 거래처 목록·메일 주소·운영 주의(IMAP 제한·시행일 정의·판정 근거)는 `sourcing-channels.md` §③ 거래처 단가표 — 운영 주의가 정본.

## 절차

```
1. python tools/tool-naver-mail-fetch.py [--vendor {거래처}]
     → 네이버 메일함(IMAP)에서 거래처 문서에 적힌 거래처 이름·메일 주소로 찾아 단가표 xlsx/pdf 를 받는다(output/sourcing/).
     --vendor 를 주면 그 거래처가 보낸 메일만. 기본 매입 폴더만(--all 로 전체).
     ⛔ --keywords 는 쓰지 않는다 — 제목 글자로 찾으면 고객 견적 문의·남의 사업자등록증까지 받힌다.
     거래처 추가 = 거래처 문서에 한 줄 (코드·옵션 수정 없음). 보내는 쪽 메일은 무엇이든 되고, 받는 메일함만 네이버여야 한다.
     메일로 받지 않는 거래처는 받은 파일을 위 폴더에 직접 넣는다 — 2번부터는 같다.
2. python tools/tool-pricebook-intake.py            ← dry-run: 받은 PDF마다 판정 표시
       ✅ auto = «단가표» 문구·거래처 1곳·시행일 1개·아는 표 양식으로 파싱·행수 ≥ 기존 CSV×0.5 → 확실한 전체본
       🗄 보관 = 못 읽었거나 조금만 읽힌 파일인데 그 거래처 최신 판보다 이전 시행일 → 묻지 않고 옮겨 두기만 한다 (가격은 최신 판에서 읽는다)
       ⏭ 건너뜀 = 같은 거래처·같은 시행일 파일이 여럿 → 가장 늦게 받은 전체본 하나만 옮기고 앞선 발송본·발췌본은 그대로 둔다
                 (받은 날짜 = 파일의 수정한 날짜 — 메일 받기 도구가 메일 날짜로 맞춘다)
                 폴더에 같은 시행일 파일이 이미 있으면 먼저 받은 파일은 건너뛰고, 더 늦게 받은 파일(정정 재발송)만 ❓ 확인으로 남긴다
       ❓ ask  = 견적서·발췌본 의심(행수 부족)·시행일 동수 2종류·거래처 미감지·못 읽는 표 양식·새 거래처 → 사용자 확인
       ⛔ skip = «단가표» 문구도 없고 파싱도 0건 → 청구서·공문·성적서, 안 건드림
   python tools/tool-pricebook-intake.py --apply     ← auto 는 자동으로 .claude/references/sourcing-prices/{거래처}/{YYYY-MM-DD}_단가표.pdf
   🔴 HITL ① 새 거래처(«비교할 기존 CSV 없음») = 첫 확인 한 번:
        python tools/tool-pricebook-intake.py --first-check --file {파일}
        → 표본 10행 + 자체 검사를 사용자에게 그대로 보여 주고 **질문은 하나** — «이 표본이 단가표 PDF 의 같은 칸과 같습니까?»
          같으면 --apply --file {파일} --vendor {거래처} 로 옮긴다 (그 뒤로 이 거래처는 auto).
          다르거나 자체 검사에 ⚠️ 가 있으면 3번의 «읽기 설정»을 고친 뒤 다시 본다.
        ⭐ 같은 새 거래처의 ❓ 가 여럿이면 **가장 늦은 시행일의 전체본 하나만** 첫 확인한다. 그 파일을 옮기고 3번(읽기)까지 끝낸 뒤
           2번을 다시 돌리면 나머지 이전 판은 🗄 보관으로 바뀐다(비교할 CSV 가 생겼기 때문) — 그 파일들은 사람에게 묻지 않고 --apply 로 보관한다.
   🔴 HITL ② 그 밖의 ask 건은 사용자에게 파일별로 확인받은 뒤 --apply --file {파일} --vendor {거래처} [--date YYYY-MM-DD] 로 하나씩 이동.
   ⭐ 시행일 = PDF 표지·라벨·내지에 기재된 «… 시행» 날짜 — 메일 수신일·첨부명 날짜 아님.
      글꼴에 글자 정보가 없는 PDF 표지는 맥 내장 OCR(tools/ocr-vision.js)로 읽는다. 쪽마다 시행일이 다르면
      (예: 대부분 쪽이 6/26, 한 쪽만 6/30) 파일명은 다수 쪽 날짜, CSV 는 **행마다 그 쪽의 날짜**를 기록한다. 감지 0건·동수면
      --date 없이는 안 옮긴다 — 사용자이 PDF 를 눈으로 보고 확정한다(추정 금지). --force 는  없이 쓰지 않는다.
   (청구서·등록증·공문은 «단가표» 문구가 없어 --force 없이는 안 옮겨진다 — sourcing/ 하위 _청구서/·_기타/ 로 손 이동,
    sourcing-channels.md §③ 거래처 단가표 — 운영 주의, «순수 단가표만 보관» 규칙).
3. python tools/tool-pricebook-parse.py --vendor {거래처}          ← --file 생략 = 최신 단가표 자동 선택
   → {거래처}-단가-정규화.csv (품번·품명·규격·개당단가·시행일). 행 시행일 = 그 쪽에 기재된 날짜(없으면 파일명 날짜).
   ⭐ 최신 단가표 = 기준: 폴더의 `*단가표*.pdf` 중 파일명 날짜 최신을 고른다.
      --file 로 명시했는데 이미 기록된 시행일보다 오래되면 **거부**한다(--force 로만 허용) — 옛 단가표를
      돌려 인상 전 가격으로 되돌아가는 사고 방지. 파일명은 `YYYY-MM-DD_단가표.pdf` 로 통일(한 시행일에 하나).
      파일명 날짜가 PDF 기재 날짜에 없으면 파싱 전에 멈춘다.
   ⚙️ 거래처별 읽기 설정 — 기본 방식으로 안 읽히는 거래처만 거래처 폴더에 둔다. 파일이 없으면 기본 방식.
      {거래처}-읽기-설정.json
        «글자표»    글자가 (cid:번호) 로 나올 때 (예: "Adobe-Korea1" — 한글 표준 글자표)
        «표지 이름» 표지에 상호가 거래처 문서와 다른 글자로 적혔을 때 (예: ["BRAND-NAME"]) — 거래처 문서 비고 칸의 «표지 이름: …» 도 같이 쓴다
                    (폴더가 아직 없는 새 거래처는 문서에 적는다)
        «칸 나누기» "기본" / "선 위치" — 빈 칸이 있는 줄의 값이 밀리거나 옆 칸 숫자가 붙을 때
        «포장 줄»   "바로 위" / "위 전부" — 포장 줄 하나가 그 위 값 줄 여럿의 포장일 때
        «제목 읽기» "기본" / "줄 단위" — 표 제목이 갈라지거나 옆 그림 설명과 붙어 읽힐 때
      {거래처}-품명-대응표.csv  (표 이름 · 줄 이름 → 품명 · 규격 앞)
        **단가표의 표 제목을 그대로 품명으로 쓰지 않고 다듬어 쓰는 거래처만** 필요하다.
        예: 표 하나 «410 #8 (4.2) 와샤붙이, 냄비, 접시 머리» 를 머리 모양별 품명 셋으로 나눠 쓴다 (견본 `examples/견본-거래처-품명-대응표.csv`).
      ⛔ 이미 잘 읽히는 거래처에 설정을 넣거나 기본 방식을 바꾸면 품명이 달라진다 — 한 번 정한 방식을 유지한다.
※ 스캔본·손글씨 단가표는 읽지 못한다 — 거래처에 PDF(글자가 선택되는 것)나 엑셀로 받는다.
```

## 교차 대조 — 어떤 품목을 어느 거래처가 얼마에 주는가

```
python3 tools/tool-pricebook-parse.py --lookup {키워드}
  → 전 거래처 정규화 CSV에서 품명·규격 대조 + 거래처별 최저가 요약.
  0건이면 그 품목을 다루는 거래처가 없다 — 다른 수집 방식(국내 도구·해외 명세)의 값이 원가 기준이 된다.
  ⚠️ 시행일이 오래된 거래처는 실발주 전 현재가를 다시 확인한다(인상 공문이 따로 왔을 수 있다).
```

## 완료 보고

- 거래처별: 채택 파일명·시행일·정규화 행수·단가 변동 건수(인상/인하). 숫자는 도구 출력·CSV에서 읽는다.
- ask 로 남은 파일과 이유. 옮기지 않은 파일(skip)은 목록만.
